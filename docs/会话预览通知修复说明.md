# 会话预览通知错误修复说明

## 问题描述

在后台模式下收到会话预览更新通知时，出现以下错误：

```
flutter: [ERROR] ❌ [ ConversationPreviewNotificationService._showSystemNotification :159] -> 显示系统通知失败 
错误: type '_Map<String, Object>' is not a subtype of type 'Message'
```

## 问题原因

在 `ConversationPreviewNotificationService._showSystemNotification` 方法中，`_createMockMessageFromPreview` 方法返回了一个 `Map<String, Object>` 对象，但 `MessageNotificationService.showMessageNotification` 方法期望的是一个真正的 `Message` 对象。

## 修复方案

### 1. 导入正确的Message模型
```dart
// 新增导入
import 'package:cc/core/database/models/message.dart' as models;
```

### 2. 修复 _createMockMessageFromPreview 方法

**修复前：**
```dart
dynamic _createMockMessageFromPreview(
  conversation_proto.ConversationPreviewUpdated previewUpdate
) {
  return {
    'messageId': 'preview_${previewUpdate.conversationId}_${DateTime.now().millisecondsSinceEpoch}',
    'content': previewUpdate.lastMessagePreview,
    'senderId': 'unknown',
    'conversationId': previewUpdate.conversationId,
    'createdAt': previewUpdate.hasLastMessageTime() 
        ? DateTime.fromMillisecondsSinceEpoch(previewUpdate.lastMessageTime.toInt())
        : DateTime.now(),
    'type': 'text',
  };
}
```

**修复后：**
```dart
models.Message _createMockMessageFromPreview(
  conversation_proto.ConversationPreviewUpdated previewUpdate
) {
  // 创建一个真正的Message对象用于通知
  final message = models.Message()
    ..messageId = 'preview_${previewUpdate.conversationId}_${DateTime.now().millisecondsSinceEpoch}'
    ..conversationId = previewUpdate.conversationId
    ..senderId = 'unknown' // 无法从preview获取具体senderId
    ..senderName = previewUpdate.lastMessageName
    ..text = previewUpdate.lastMessagePreview
    ..type = models.MessageType.text // 假设为文本消息
    ..status = models.MessageStatus.sent
    ..messageIndex = previewUpdate.lastMessageIndex.toInt()
    ..createdAt = previewUpdate.hasLastMessageTime() 
        ? DateTime.fromMillisecondsSinceEpoch(previewUpdate.lastMessageTime.toInt())
        : DateTime.now();
  
  return message;
}
```

## 修复详细说明

### 1. 类型安全修复
- **问题**: 返回类型从 `dynamic` 改为具体的 `models.Message`
- **好处**: 提供编译时类型检查，避免运行时类型错误

### 2. 正确的对象创建
- **问题**: 从创建 Map 对象改为创建真正的 Message 实例
- **好处**: 符合 `MessageNotificationService` 的期望，确保兼容性

### 3. 完整的字段映射
- **新增字段**: `senderName`, `status`, `messageIndex` 等必要字段
- **字段映射**: `content` → `text`（根据Message模型的实际字段名）
- **类型转换**: 正确使用 `models.MessageType.text` 和 `models.MessageStatus.sent`

### 4. 时间处理
- **保持**: 原有的时间戳处理逻辑
- **改进**: 使用 Message 模型的 `createdAt` 字段

models.MessageType detectMessageType(String preview) {
  if (preview.startsWith('[图片]')) return models.MessageType.image;
  if (preview.startsWith('[语音]')) return models.MessageType.voice;
  if (preview.startsWith('[视频]')) return models.MessageType.video;
  if (preview.startsWith('[文件]')) return models.MessageType.file;
  return models.MessageType.text;
}
