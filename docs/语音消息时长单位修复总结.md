# 语音消息时长单位修复总结

## 问题发现
用户反馈：Message模型里有duration字段，但语音消息不显示预存时长，而是显示"--:--"。

## 问题根源分析

### 单位不一致问题
在整个语音消息流程中，duration的单位定义混乱：

1. **VoiceRecordResult.duration** - 秒 (seconds)
   ```dart
   class VoiceRecordResult {
     final int duration; // 秒
   }
   ```

2. **Message.duration** - 毫秒 (milliseconds)
   ```dart
   int? duration; // 语音/视频时长(毫秒)
   ```

3. **数据传递链路**：
   ```
   VoiceRecordService (秒) 
   → ChatPage.sendVoiceMessage (秒) 
   → ChatCubit.sendVoiceMessage (传递原值) 
   → ChatRepositorySend.sendVoiceMessage (存储到Message.duration)
   ```

### 错误的地方
- ChatPage调用`chatCubit.sendVoiceMessage(recordResult.duration)`时，传递的是秒数
- 但Message.duration字段期望的是毫秒数
- 结果：数据库中存储的duration值比实际小1000倍

## 修复方案

### 1. ChatPage中的修复

#### 发送消息修复
```dart
// 修复前
await chatCubit.sendVoiceMessage(
  recordResult.filePath,
  recordResult.duration, // 错误：传递秒数给期望毫秒的字段
  mediaUrl: uploadResult.remoteUrl,
);

// 修复后
await chatCubit.sendVoiceMessage(
  recordResult.filePath,
  recordResult.duration * 1000, // 🔧 转换为毫秒
  mediaUrl: uploadResult.remoteUrl,
);
```

#### 文件上传修复
```dart
// 修复前
final uploadResult = await _fileUploadService.uploadVoice(
  File(recordResult.filePath),
  recordResult.duration, // 错误：传递秒数给期望毫秒的上传API
);

// 修复后
final uploadResult = await _fileUploadService.uploadVoice(
  File(recordResult.filePath),
  recordResult.duration * 1000, // 🔧 转换为毫秒，与数据库和proto保持一致
);
```

### 2. MediaUploadIntegrationService中的修复
```dart
// 修复前
final message = await _chatRepository.sendVoiceMessage(
  conversationId,
  voiceFile.path,
  duration ~/ 1000, // 错误：将毫秒转换为秒，但期望毫秒
  mediaUrl: uploadResult.url,
);

// 修复后
final message = await _chatRepository.sendVoiceMessage(
  conversationId,
  voiceFile.path,
  duration, // 🔧 duration参数已经是毫秒，直接传递
  mediaUrl: uploadResult.url,
);
```

## 数据流修复后的正确流程

```
1. VoiceRecordService.stopRecording() 
   → 返回 VoiceRecordResult(duration: 5) // 5秒

2. ChatPage._uploadAndSendVoice() 
   → 调用 uploadVoice(file, 5 * 1000) // 转换为5000毫秒上传
   → 调用 sendVoiceMessage(path, 5 * 1000) // 转换为5000毫秒发送

3. UploadApiService.uploadVoice()
   → 发送到服务器 metadata: {'duration': '5000'} // 毫秒字符串

4. ChatCubit.sendVoiceMessage() 
   → 接收 duration: 5000 // 毫秒

5. ChatRepositorySend.sendVoiceMessage() 
   → 设置 message.duration = 5000 // 存储毫秒

6. MessageAdapter.toProto()
   → 发送给服务器 mediaMessage.duration = 5000 // 毫秒

7. VoiceMessageWidget._initializeDuration() 
   → Duration(milliseconds: 5000) // 正确解析为5秒
```

## 验证修复效果

### 修复前的症状
- 数据库中duration值异常小（如5而不是5000）
- VoiceMessageWidget显示"--:--"因为duration < 1000毫秒
- 语音消息UI宽度异常小

### 修复后的效果
- 数据库中duration正确存储毫秒值
- VoiceMessageWidget正确显示预存时长
- 语音消息UI宽度根据真实时长计算
- 播放前就能看到准确的时间信息

## 技术要点

### 单位转换规则
- **录制服务输出**：秒 (便于用户理解)
- **数据库存储**：毫秒 (精度更高)
- **UI显示**：自动格式化 (MM:SS)

### 防范措施
1. 在关键接口添加单位注释
2. 使用类型安全的Duration对象
3. 统一转换逻辑集中处理

## 影响范围
- ✅ 新录制的语音消息：立即生效
- ⚠️ 已存在的语音消息：需要重新播放获取真实时长
- ✅ 所有媒体上传服务：修复了错误转换
- ✅ 与服务器通信：确保proto消息中duration为毫秒
- ✅ 文件上传API：duration元数据统一为毫秒

## 总结
通过修复单位转换错误，语音消息现在能够正确显示预存时长信息，解决了UI显示"--:--"的问题。这是一个典型的数据类型和单位一致性问题，提醒我们在API设计时要明确单位定义。
