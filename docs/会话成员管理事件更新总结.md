# 会话成员管理事件更新总结

## 🔄 更新背景
用户对`conversation.proto`文件进行了重构，将Request/Response消息配对放置，并更新了会话成员管理相关的消息类型。

## 📝 主要变更

### 1. Proto消息类型重命名
- ✅ `ConversationMemberRequest` → `ConversationMemberChangeRequest`
- ✅ 新增 `ConversationMemberChangeResponse` 消息类型
- ✅ 移除了原来的 `ConversationMemberChangeNotification`（用`ConversationMemberChangeResponse`替代）

### 2. Proto文件结构重组
```
// 原来的结构（随机排列）
message ConversationMemberRequest { ... }
message ConversationMemberChangeNotification { ... }
// 其他消息...

// 新的结构（Request/Response配对）
// ================================
// 会话成员管理 (Member Management)  
// ================================
message ConversationMemberChangeRequest { ... }
message ConversationMemberChangeResponse { ... }
```

### 3. Socket.io事件映射更新

#### 客户端发送事件
```dart
// 会话成员管理请求
'conversation:member:change' → ConversationMemberChangeRequest
'conversation:member:add' → ConversationMemberChangeRequest
```

#### 服务器响应事件
```dart
// 会话成员管理响应（可选，直接响应客户端请求）
'conversation:member:changed:response' → ConversationMemberChangeResponse

// 会话成员变更通知（广播给所有相关用户）
'conversation:member:changed' → ConversationMemberChangeResponse
```

### 4. 客户端代码更新

#### proto_events.dart
- ✅ 更新事件映射表，使用新的消息类型
- ✅ 添加`conversation:member:changed:response`事件映射

#### chat_repository_impl.dart
- ✅ 更新所有成员管理方法：
  - `updateMemberRole()`
  - `removeMemberFromConversation()`
  - `blockMemberInConversation()`
- ✅ 添加`conversation:member:changed`事件监听器
- ✅ 实现`_handleMemberChangeNotification()`处理方法

### 5. 事件处理逻辑

#### 客户端请求流程
```dart
// 1. 客户端发送请求
ConversationMemberChangeRequest request = ConversationMemberChangeRequest()
  ..conversationId = conversationId
  ..userId = userId
  ..action = 'promote'; // add, remove, promote, demote, block

await _communicationService.emitProto('conversation:member:change', request);
```

#### 服务器通知处理
```dart
// 2. 监听服务器广播通知
_communicationService
    .onProto<ConversationMemberChangeResponse>('conversation:member:changed')
    .listen(_handleMemberChangeNotification);

// 3. 处理成员变更通知
void _handleMemberChangeNotification(ConversationMemberChangeResponse notification) {
  switch (notification.action) {
    case 'added': // 成员加入
    case 'removed': // 成员移除  
    case 'promoted': // 权限提升
    case 'demoted': // 权限降级
    case 'blocked': // 成员屏蔽
  }
}
```

## 🎯 实现效果

### 统一的消息结构
所有会话成员管理操作现在使用统一的Request/Response模式：
- 请求：`ConversationMemberChangeRequest`
- 响应：`ConversationMemberChangeResponse`（用于直接响应和广播通知）

### 清晰的事件分离
- `conversation:member:changed:response` - 服务器直接响应客户端请求
- `conversation:member:changed` - 服务器广播给所有相关用户

### 完整的客户端支持
- ✅ 可以发送所有类型的成员管理请求（添加、移除、提升、降级、屏蔽）
- ✅ 可以接收和处理服务器的成员变更通知
- ✅ 支持实时更新UI显示成员状态变化
